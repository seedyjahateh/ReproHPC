# demo-cv-v1 scientific contract

No existing domain routine was present in this repository. This implementation is the PRD's synthetic reference algorithm; it has no independent domain-scientific endorsement.

Inputs are genuine single-channel unsigned 8-bit PNGs, 1–4096 pixels per dimension. PNG IHDR is checked before allocation; palette, RGB, alpha, 16-bit, stack, and oversized data are rejected. Decoding uses OpenCV IMREAD_UNCHANGED.

Gaussian filtering uses an explicit odd kernel, explicit sigma, and BORDER_REFLECT_101 (reflect without repeating the edge pixel). Kernel 1 bypasses filtering. Foreground is strictly greater than the threshold. Connectivity is 4 or 8, with 8 the default. Keep objects with area greater than or equal to min_area_px. Include border objects and flag them.

Object order is top bounding-box coordinate, left coordinate, centroid y, centroid x, then connected-component label for a deterministic final tie-breaker. Object IDs restart at one per image. The exported mask is boolean, so OpenCV label numbering is not exposed. Areas and counts are integers. Centroids are pixel-center coordinates (zero-based, x right, y down). Intensity means use original decoded intensities, not the blurred image. Physical area is area_px × pixel_size_um² only when calibrated. Missing means/physical areas are null, never non-finite numbers.

Implementation uses a label-indexed lookup and bincount, avoiding one full image scan per component. Images are processed sequentially within a task and buffers are released between images. OpenCV uses one thread, no OpenCL and no optimized kernels. RNGs derive per-image seeds as specified in PRD section 11.

The 12 committed fixtures were generated by scripts/generate_demo.py. Expected default masks and counts come from tests/reference_oracle.py, an independent scalar Gaussian convolution and flood-fill implementation without OpenCV or production analysis imports. Unit tests also check exact analytical rectangle measurements with blur disabled. Regenerating goldens requires a scientific explanation; never copy pipeline outputs over expectations to make tests pass.

Measured behaviour on real images is recorded in [real microscopy data](real-data.md): against the expert masks of BBBC039v1, held-out count agreement is a median ratio of 0.937, with 98 of 100 images under-counted and none over-counted. That asymmetry is the expected consequence of this contract, which has no splitting step, so nuclei that touch merge into one component. It is a limitation of the routine rather than a defect in its implementation.

Changing the algorithm contract requires new algorithm/version metadata, updated independent expectations, comparison evidence, and a new immutable release.
